# 개선 효과 검증

> 상태: 직접 녹음 12개의 인식 결과와, **수작업 라벨 2개(ko_01, ko_05) + 재라벨 1개(ko_01)** 기준 타이밍·입 닫힘·시간 측정까지 반영.
> 재현: `python -m src.evaluate outputs/audio outputs/audio_raw outputs/audio_rms outputs/audio_script` → `outputs/eval/*_metrics.md`
> (`audio` = 기본 설정, `audio_raw` = 단어 경계 보정 끔, `audio_rms` = 음량 기준선, `audio_script` = 대본 힌트 켬)

## 0. 판정 규칙 (결과를 보기 전에 정함)

PoC의 산출물은 "구축할지 말지와 그 근거"다. 결과를 보고 기준을 바꾸지 않도록 판정 규칙을 먼저 적는다.

| 결과 | 판정 | 다음 행동 |
|---|---|---|
| 시간·타이밍·입 닫힘 기준 모두 통과 | **구축** | 대량 배치, DCC 임포트, 수정 레이어 보존 |
| 시간·입 닫힘 통과, **타이밍만 미달** | **조건부 구축** | 정렬기를 MFA로 교체 후 같은 라벨로 재검증 (`Aligner` 인터페이스) |
| **입 닫힘 미달** | 보류 | 매핑값/MBP 유지 시간/프레임레이트 조정 후 재검증. 정렬기 문제가 아니므로 모델 교체로는 해결 안 됨 |
| 음량 기준선이 Whisper 파이프라인과 차이 없음 | **보류** | AI 도입 근거 없음 — 기존 간이 방식 유지 |

성공 기준 (`problem_definition.md` 6장):
시간 단축 ≥ 90% · 모음 시작 평균 오차 ≤ 2프레임 **그리고** ≤ 사람끼리의 오차 · 재현율 ≥ 0.9 · MBP 적중률 ≥ 80%

## 2. 값의 검증 — 재려던 것을 실제로 재고 있는가

지표를 새로 넣을 때마다, 답을 알고 있는 입력으로 따로 확인했다.

> **이 장의 수치는 사람 라벨이 아니라 합성 라벨로 낸 값이다.** 파이프라인 예측을 일부러 변형해 만든 라벨이라
> "지표가 계산을 제대로 하는가"만 보여 주고, 립싱크 품질과는 무관하다. 재현: `python -m src.selfcheck` (6개 항목 통과 확인).

| 지표 | 확인 방법 | 결과 | 조치 |
|---|---|---|---|
| 모음 시작 오차 | 예측을 **3프레임 늦춘 합성 라벨**로 채점 (답: 오차 3, 편향 −3) | 처음엔 **2.17**로 과소 측정. 촘촘한 한국어 모음에서 정답-예측이 한 칸씩 어긋나 짝지어짐 | 라벨 이름의 입모양 그룹이 다르면 벌점 → **3.0 / −3.0 재현** |
| 모음 시작 오차 (평균) | 같은 합성 라벨로 음량 기준선 채점 | 기준선이 13개 중 **6개만** 찾고도 평균 1.81로 더 좋아 보임 — 평균은 짝지어진 것만 계산하므로 **적게 찾을수록 좋아 보이는 지표** | **재현율**을 추가하고 기준에 "재현율 ≥ 0.9"를 걺. **놓친 모음을 9프레임으로 넣은 평균**(`onset_mae_capped_f`)도 병기 |
| MBP 적중률 | MBP 6개 중 1개를 엉뚱한 위치로 옮긴 합성 라벨 (답: 5/6, 잘못 닫힘 1) | 0.833, 잘못 닫힘 1 ✅ | 놓친 것만 세면 자주 닫을수록 유리하므로 **잘못 닫힌 횟수**를 함께 셈 |
| CER (인식 오류) | 음량 기준선(전사 없음)에 적용 | 1.0으로 계산됨 — 인식을 안 하는 방식에 의미 없는 값 | 전사가 없으면 CER을 비움 |
| CER 기준값 0.1 | small 모델 TTS ko_05 ("같이 **이** 국물") | 단어가 끼어든 진짜 오류인데 13글자 중 1글자라 **0.08** → "오류 아님"으로 분류 | 짧은 대사에서는 단어 단위 비교가 맞음. 보고 시 함께 표기 |
| CER 자체 | "crazy → 크레이지", "네가 → 내가" | 표기만 다르고 **입모양은 거의 같은데** 오류로 셈 | 립싱크 품질은 타이밍·MBP 지표가 우선. CER은 인식 실패 탐지용 |
| 대본 힌트 실행의 CER | `--use-script`로 대본을 프롬프트에 넣음 | 12개 모두 대본과 일치 — **힌트가 정답을 알려 준 것**이라 정확도로 쓸 수 없음 | 이 실행의 CER은 보고하지 않는다. 타이밍은 라벨로 따로 확인 |
| 검수 표시 (신뢰도 < 0.6) | TTS로 정한 임계값을 직접 녹음으로 재확인 | TTS에서는 오인식을 모두 잡았지만 **녹음에서는 3건 중 2건을 놓침** (확신하면서 틀림) | `model_selection.md` 7장. 대본 비교를 우선하고 신뢰도는 보조로 둠 |

### 지표의 알려진 한계 (검수에서 확인)

| 한계 | 내용 |
|---|---|
| "모음 시작"은 커브가 아니라 **음소 구간 경계**를 잰다 | 예측 시작 시각은 단어 구간을 가중치로 나눈 경계다. 실제 커브의 키는 구간 **중앙**에 있어 입이 가장 벌어지는 시점은 이보다 늦다. 이 지표는 "정렬과 시간 배분이 맞는가"를 재고, 커브 모양은 재지 않는다 |
| 0.3초 넘게 어긋난 모음은 짝이 안 지어진다 | 평균 오차에서 빠지고 재현율만 떨어진다 → 상한 반영 평균을 함께 본다 |
| 음량 기준선은 모음 이름이 없다 | 이름 벌점을 받지 않아 짝짓기가 더 너그럽다. 기준선과 비교할 때는 재현율과 상한 반영 평균으로 본다 |
| 시간 단축률은 사실상 실패할 수 없다 | 3초 대 수 분이라 항상 99% 근처이고 음량 기준선도 100%다. **자동 결과를 사람이 고치는 시간**이 빠져 있다 → 1~2개 파일이라도 "자동 + 수정 시간"을 재서 병기 |
| 현행 수준 표본이 작다 | 같은 사람이 ko_01 하나를 두 번 라벨링한 값 (n=1) |
| 언어 자동 감지는 평가되지 않았다 | 대본에 언어가 있으면 그 값을 쓰므로, 이번 측정은 모두 언어를 알려 준 상태다 |

## 3. 결과

### 3-1. 현행 수준 (사람)

| 항목 | 값 |
|---|---|
| 수작업 라벨링 시간 | ko_01 **414초** (모음 14 + 입 닫힘 6), ko_05 **183초** (모음 13 + 입 닫힘 3), ko_01 두 번째 306초 |
| 사람끼리의 모음 시작 차이 (ko_01을 두 번 라벨링) | 평균 **1.63프레임**, 중앙값 1.15, 최대 4.21, 2프레임 이내 71% |
| 사람끼리의 입 닫힘 시작 차이 | 평균 0.63프레임 (6개 모두 대응) |

- 라벨링은 전용 도구(`tools/labeler.html`: 찍을 순서 제시, 느린 재생, 스펙트로그램)로 했다. Audacity로 하는 현업 작업보다 빠른 조건이라
  **수작업 시간은 실제보다 짧게 잡힌 값**이다 (자동화에 불리한, 보수적인 비교).
- **같은 사람이 같은 파일을 다시 찍어도 평균 1.6프레임이 흔들린다.** 성공 기준 2프레임은 사람의 흔들림과 거의 같은 수준이다.
- ko_05 라벨 중 입 닫힘 1개(1.75~4.01초, 2.26초 길이)는 드래그 실수로 보여 채점에서 제외했다 (0.6초 넘는 입 닫힘 라벨은 자동 제외).

### 3-2. 기준선 vs Whisper 파이프라인 (직접 녹음, 라벨 2개: ko_01, ko_05)

| 방식 | 재현율 | 모음 시작 평균 오차 | 상한 반영 평균 | 2프레임 이내 | MBP 적중 | 잘못 닫힘 | 생성 시간 |
|---|---|---|---|---|---|---|---|
| 수작업 (다시 라벨링) | 1.0 | 1.63 | 1.63 | 71% | 6/6 | 0 | 183~414초 |
| 음량 기준선 | 0.48 | 3.68 | 6.44 | 7% | 0/8 | 0 | 약 0.07초 |
| Whisper 파이프라인, 경계 보정 끔 | 0.89 | 2.88 | 3.57 | 37% | 8/8 | 3 | 약 3.0초 |
| **Whisper 파이프라인 (기본 설정)** | **1.0** | **2.38** | 2.38 | 59% | 7/8 | 2 | 약 3.2초 |
| Whisper 파이프라인 + 대본 힌트 | 1.0 | 1.86 | 1.86 | 70% | 7/8 | 2 | 약 3.4초 |

(오차 단위는 프레임, 30fps. 두 파일의 평균. 수작업 행은 ko_01 한 파일 기준)

파일별 (기본 설정):

| ID | 재현율 | 평균 오차 | 편향 | 2프레임 이내 | MBP 적중 | 잘못 닫힘 | 수작업 | 자동 | 시간 단축 |
|---|---|---|---|---|---|---|---|---|---|
| ko_01 | 1.0 | **1.49** | +0.36 | 71% | 5/6 | 1 | 414초 | 3.2초 | 99.2% |
| ko_05 | 1.0 | **3.26** | −2.24 | 46% | 2/2 | 1 | 183초 | 3.1초 | 98.3% |

읽는 법:

- **음량 기준선 대비 차이는 분명하다.** 기준선은 모음의 절반도 못 찾고(재현율 0.48) 입 닫힘은 하나도 못 만든다 (0/8). AI를 붙일 근거가 있다.
- **ko_01은 사람 수준이다.** 평균 1.49프레임으로, 사람이 다시 찍은 차이(1.63)보다 작다.
- **ko_05는 기준 미달이다.** 평균 3.26프레임. "먹자"의 ㅓ(−8.5), "좋아"의 ㅗ(−6.8), "정말"의 ㅓ(−8.1)에서 예측이 7~8프레임 빠르다.
  Whisper가 이 단어들의 시작을 실제보다 일찍 잡았고, 단어 구간을 음소 비율로 나누는 방식이 그 오차를 그대로 물려받았다.
- **대본 힌트를 주면 ko_05가 3.26 → 2.23으로 줄었다.** 인식뿐 아니라 단어 시각도 좋아졌다. 평균 1.86으로 2프레임 안에는 들지만 사람 수준(1.63)에는 못 미친다.
- **입 닫힘은 8개 중 7개 적중.** 놓친 1개는 ko_01 "바람이"의 ㅁ 받침으로, 닫힘이 몇 프레임 옆에 만들어져 "잘못 닫힘"으로 잡혔다.
- **시간 단축은 98~99%**지만, 자동 결과를 사람이 고치는 시간은 포함하지 않은 값이다.

### 3-3. 인식 결과: TTS vs 직접 녹음 (medium, 대본 힌트 없음)

| 항목 | TTS | 직접 녹음 |
|---|---|---|
| 정상 대사 8개 평균 CER | 0.010 | **0.066** |
| 한국어 정상 5개 | 모두 일치 (ko_04 "네가/내가" 표기 차이) | 3개 일치, ko_03 "길의 → 일의", ko_04 표기 차이 |
| 영어 정상 3개 | 모두 일치 | en_01 "birch canoe slid → beach cannon sight" (CER 0.24), en_02 "rises → river", en_03 일치 |
| 검수 필요 표시 | 1건 (en_02, 오경보) | 6건 (en_01, en_02, en_03, ko_03, ko_05, fail_03) |
| 파일당 생성 시간 | 약 3.2초 | 약 3.3초 |

- TTS는 실제 목소리보다 쉬운 입력이었다. **TTS만으로 검증했다면 인식 정확도를 과대평가**했을 것이다.
- 영어는 한국어 화자 발음에서 오인식이 늘었다 (3개 중 2개).
- **대본 힌트(`--use-script`)를 주면 12개 모두 대본과 일치**했고, fail_02의 "crazy", "next level"도 영어로 전사돼 영어 음소 경로를 탔다.
  게임 대사는 대본이 있으므로 실무 기본값은 대본 힌트를 켜는 쪽이 맞다. 단, 타이밍이 좋아졌는지는 라벨로 확인해야 한다.

| 같은 모음이 이어지면("하아") 채점에서 한 개로 셈 | 재현율이 실제보다 낮게 나옴 | 음절 단위로 따로 세도록 수정 |
| ㅐ/ㅔ처럼 표기만 다른 모음을 다른 모음으로 취급 | "네가/내가"에서 짝짓기 탈락 | 입모양 그룹으로 비교 |
| 숫자 등 음소가 없는 단어가 조용히 사라짐 | 입이 안 움직이는데 표시도 없음 | 검수 필요로 표시 |

## 5. 추가 시도

| 시도 | 가설 | 결과 |
|---|---|---|
| 대본 힌트 (`--use-script`) | 대본을 알려 주면 인식 오류가 줄어든다 | 녹음 12개 모두 대본과 일치. 타이밍도 개선: 모음 시작 평균 오차 2.38 → **1.86**프레임 (ko_05 3.26 → 2.23, ko_01 변화 없음) |
| g2pk 발음 규칙 (같이→가치, 국물→궁물, 좋아→조아) | 실제 소리대로 음소를 만들면 입모양이 맞아진다 | (예정) |
| 음량으로 단어 경계 보정 (기본 켜짐, 끄려면 `--no-refine-boundaries`) | Whisper의 문장 시작 오차와 단어 안의 쉼을 음량으로 잡을 수 있다 | 무음인데 입이 열린 프레임: 녹음 정상 8개 합계 **149 → 23**, TTS 75 → 30. 아래 5-1 |

### 5-1. 음량으로 단어 경계 보정

Whisper는 단어를 빈틈 없이 이어 붙인다. 직접 녹음에서 이 문제가 TTS보다 훨씬 크게 나타났다.

| 사례 | Whisper 단어 시각 | 실제 소리 | 보정 후 |
|---|---|---|---|
| ko_04 "내가" | 0.00 ~ 1.78초 | 1.45초부터 (녹음 앞 여백) | 1.40 ~ 1.78초 |
| en_01 "the" | 1.58 ~ 2.68초 | 1.97초에 끝나고 0.67초 무음 | 1.58 ~ 2.00초 |
| fail_01 "바람이" | 0.00 ~ 0.88초 | 0.54초부터 (그 전은 0.05초 이하의 짧은 소리) | 0.49 ~ 0.88초 |

보정 전에는 ko_04에서 **소리가 나기 전 1.4초 동안 입이 서서히 벌어졌다** (`outputs/compare/audio_raw_vs_audio/ko_04_compare.png`, 보정 전 결과는 `outputs/audio_raw/`).

방법 (`src/boundary.py`): 10ms 단위 음량으로 소리 구간을 찾고, 단어 앞뒤에 붙은 무음만 잘라 낸다.
- 단어 앞은 0.05초 여유를 남긴다 (ㅂ ㄱ 같은 파열음은 소리 직전에 닫힘 구간이 있다).
- 단어 안에 0.2초 넘는 무음이 있으면 소리가 긴 쪽만 그 단어로 본다 (파열음의 닫힘은 이보다 짧다).
- 0.06초보다 짧은 소리는 잡음으로 무시한다.

무음인데 입이 열린 프레임 수 (무음 = 큰 소리의 12% 미만이 ±20ms 이어짐, 입 열림 = jawOpen > 0.1):

| ID | 보정 전 | 보정 후 | 음량 기준선 |
|---|---|---|---|
| ko_01 | 27 | 1 | 0 |
| ko_04 | 39 | 4 | 0 |
| ko_05 | 14 | 3 | 1 |
| en_01 | 23 | 0 | 0 |
| en_03 | 42 | 11 | 3 |
| fail_01 | 14 | 2 | 2 |
| fail_03 | 36 | 4 | 0 |
| **정상 8개 합계** | **149** | **23** | 7 |

**수작업 라벨로 확인한 결과** (위 지표와 달리 보정과 독립적인 정답):

| ID | 보정 끔: 재현율 / 평균 오차 / 상한 반영 | 보정 켬: 재현율 / 평균 오차 / 상한 반영 |
|---|---|---|
| ko_01 | 0.86 / 2.19 / 3.16 | **1.0 / 1.49 / 1.49** |
| ko_05 | 0.92 / 3.56 / 3.98 | **1.0 / 3.26 / 3.26** |

보정 후 두 파일 모두 놓치는 모음이 없어졌고 오차도 줄었다. 다만 입 닫힘은 8/8 → 7/8로 하나 줄었다
(ko_01 "바람이"의 ㅁ 받침. 단어 구간이 바뀌며 닫힘 위치가 라벨에서 몇 프레임 벗어남).

이 결과의 한계:
- **무음 중 입 열림 지표는 보정이 쓰는 것과 같은 음량 기준으로 무음을 정한다.** 그 지표만으로는 "보정이 의도대로 동작한다"는 확인일 뿐이라,
  위 표처럼 수작업 라벨로 따로 확인했다. 라벨은 2개 파일뿐이다.
- ko_05의 "먹자", "좋아", "정말"은 보정 후에도 단어 시작이 일찍 잡혀 있다. 음량 보정이 이 구간을 못 잡은 이유는 확인하지 못했다.
- 음량 기준선은 이 지표에서 당연히 가장 좋다 (음량이 곧 입 벌림이므로). 기준선의 약점은 입모양과 입 닫힘이다.
- fail_01의 0.54초 이전 짧은 소리가 잡음인지 "바"의 일부인지는 듣거나 라벨로 확인해야 한다.
- Whisper가 단어를 실제보다 **늦게** 시작한 경우는 다루지 않는다.

## 6. 결론: 구축 여부

0장의 판정 규칙을 그대로 적용한다 (기본 설정, 라벨 2개 기준).

| 기준 | 결과 | 판정 |
|---|---|---|
| 시간 단축 ≥ 90% | 98.3~99.2% (수정 시간 미포함) | 통과 |
| 모음 재현율 ≥ 0.9 | 1.0 | 통과 |
| 모음 시작 평균 오차 ≤ 2프레임, 그리고 ≤ 사람끼리의 차이(1.63) | 평균 2.38 (ko_01 1.49 통과, ko_05 3.26 미달) | **미달** |
| MBP 적중률 ≥ 80% | 7/8 = 87.5% (잘못 닫힘 2) | 통과 |
| 음량 기준선보다 나은가 | 재현율 1.0 vs 0.48, MBP 7/8 vs 0/8 | 통과 |

**판정: 조건부 구축.** 시간과 입 닫힘은 통과했고 타이밍만 미달이다. 미리 정한 규칙대로 **정렬기를 MFA로 교체한 뒤 같은 라벨로 재검증**한다.

근거:
- 미달의 원인은 Whisper의 단어 시각이다. ko_05에서 오차가 큰 모음은 모두 단어 시작이 일찍 잡힌 단어에 몰려 있다.
  MFA는 대본을 받아 음소 단위 시각을 주므로, 단어 구간을 비율로 나누는 단계 자체가 없어진다 (모델 선정 점수 1위였던 후보).
- 음소 → 입모양 → ARKit 커브 단계는 유지한다. 단어 시각이 맞은 ko_01에서는 사람 수준(1.49 vs 1.63)이 나왔다.
- 당장 쓸 수 있는 개선: 대본 힌트를 기본으로 켠다 (평균 2.38 → 1.86). 2프레임 안에는 들지만 사람 수준에는 못 미친다.

이 결론의 한계:
- 라벨이 **2개 파일, 화자 1명**뿐이고, 사람끼리의 차이는 파일 1개로 잰 값이다. 결론이 바뀔 수 있는 표본 크기다.
- 지표는 음소 구간 경계를 잰다. 커브 모양이 자연스러운지는 재지 못했다 (영상으로 본 정성 평가만 있음).
- 자동 결과를 사람이 고치는 시간은 재지 않았다. 실제 절감 폭은 98%보다 작다.
