## 1. 적은 세 지점 중에서 고른 것과 뺀 것의 차이는 무엇이었습니까?

| 옵션 | 대상 직군 | 업무 유형 | 결과 |
|---|---|---|---|
| **1. 음성(STT) 기반 자동 페이셜 립싱크 데이터 생성기** | 리거, 애니메이터, TA | 입력과 전사 (소리 → 입모양 키) | **선택** |
| 2. YOLO-Pose 기반 레퍼런스 영상 → 뼈대(Joint) 베이스 키프레임 추출기 | 애니메이터, TA | 입력과 전사 (영상 → 관절 키) | 뺌 |
| 3. SAM 기반 메쉬/웨이트 칠하기(Selection) 자동화 보조 툴 | 리거, CFX 아티스트 | 검사와 판독 (영역 판별) | 뺌 |

### 끌렸던 두 개 (1, 2)의 차이: 결과까지 가는 거리

옵션 1과 2는 둘 다 "사람이 보고 들으며 키를 옮겨 적는 일"이라 같은 유형이고, 둘 다 끌렸다.
차이는 **AI 출력과 실제로 필요한 결과 사이의 거리**였다.

- **옵션 2**: YOLO-Pose가 주는 것은 영상 속 **2D 관절 좌표**다. 애니메이션에 필요한 것은 **3D 리그의 관절 회전값**이다.
  그 사이에 깊이 추정, 뼈 길이 제약, 회전값 계산(IK, 짐벌락 등 회전 처리), 리그 리타게팅이 모두 들어간다.
  모델 하나를 붙이는 게 아니라 3D 환경 처리를 따로 준비해야 해서 **2일 안에 입력→처리→출력을 끝내기 어렵다**고 판단했다.
  검증도 어렵다. 정답(3D 관절 회전)을 만들려면 모션캡처 같은 장비가 필요해서 **판정 기록을 직접 만들 수 없다**.
- **옵션 1**: Whisper가 주는 단어 타이밍에서 ARKit 값까지는 **규칙(음소 → 비짐 → 블렌드쉐입)으로 이어진다**.
  정답도 **직접 만들 수 있다**. 내 목소리를 녹음하고 Audacity로 라벨을 찍으면 된다.

### 옵션 3을 뺀 이유: 기준선이 이미 이긴다

메쉬 선택이나 웨이트 칠하기는 **이미 쓸 만한 무료 도구가 많다**고 알고 있다 (예: Blender 자동 웨이트).
강의의 "기준선이 이기면 그것도 결과"에 해당한다. 지금 방식(기존 도구)이 충분하면 AI를 새로 붙일 근거가 약하다.
또 SAM은 **2D 이미지**를 분할하는 모델이라, 3D 메쉬 선택에 쓰려면 여러 시점에서 렌더링한 결과를 메쉬로 되돌리는
과정이 필요하다. 옵션 2와 같은 "2D → 3D" 거리 문제도 있다.

### 한 줄 정리

> 고른 것은 **AI 출력에서 결과까지 규칙으로 이어지고, 정답을 내가 직접 만들어 채점할 수 있는** 일이었다.
> 뺀 것은 **2D 출력을 3D로 옮기는 준비가 커서 기간 안에 검증까지 못 가는 일(옵션 2)**과,
> **기존 무료 도구라는 기준선이 이미 충분한 일(옵션 3)**이었다.

옵션 2는 버린 게 아니라 미룬 것이다. 이번 PoC에서 만든 구조(정렬 → 규칙 매핑 → 키 출력, 라벨 기반 채점)는
옵션 2에도 그대로 쓸 수 있다.

## 2. 성공 기준의 숫자를 어디서 가져왔습니까? 현행 수준을 실제로 재 보았습니까?

| 기준 | 출처 | 현행 수준 실측 |
|---|---|---|
| 시간 단축 90% | 수작업 라벨링 시간 대비 | **쟀다.** 대사 1줄에 183~414초 (전용 라벨링 도구 기준이라 현업보다 짧은 값) |
| 모음 시작 2프레임 | 30fps에서 입모양이 소리와 어긋나 보이기 시작하는 통상적인 허용 범위 | **쟀다.** 같은 파일(ko_01)을 두 번 라벨링한 차이가 평균 **1.63프레임** (최대 4.21) |
| MBP 80% | 사람은 사실상 100%. 나머지를 사람이 고칠 수 있는 수준 | 두 번 라벨링에서 입 닫힘 6개가 모두 대응, 시작 차이 평균 0.63프레임 |

처음 초안에는 숫자만 있었고 현행 수준을 재지 않았다. 강의 내용을 반영해 "사람끼리의 오차"를 재는 절차를 추가했다.

재 보고 알게 된 것:
- **2프레임이라는 기준은 사람의 흔들림(1.63)과 거의 같았다.** 사람도 같은 파일을 다시 찍으면 그만큼 달라진다.
  "사람보다 정확하게"가 아니라 "사람만큼"이 현실적인 목표라는 것을 숫자로 확인했다.
- 직접 라벨링해 보니 짧은 음성에서 모음 시작과 입 닫힘을 찍는 일 자체가 어렵고 오래 걸렸다 (3초 대사에 3~7분).
  이 경험이 "입력과 전사 업무의 병목은 양"이라는 문제 정의를 뒷받침한다.
- 한계: 사람끼리의 차이는 파일 1개, 같은 사람이 잰 값이다. 다른 사람과의 차이는 재지 못했다.

## 3. 실행 위치나 라이선스 때문에 제외한 후보가 있었습니까? 그 후보가 점수로는 몇 위였습니까?

| 후보 | 제외 사유 | 점수 순위 |
|---|---|---|
| 클라우드 음성 인식 (CLOVA Speech, Google STT) | **실행 위치**: 미공개 성우 음성을 외부 서버로 보내야 함 | **2위** (77점) — 한국어 인식 품질 최상위권 |
| NVIDIA Audio2Face-3D | **실행 환경**: NVIDIA GPU, CUDA 12.8, TensorRT 필수라 CPU 재현 불가 | 5위 (69점) |

라이선스 때문에 제외한 후보는 없었다. 확인한 오픈소스 후보는 모두 상업적 사용이 가능했다. MFA 한국어 모델은 CC BY 4.0이라 출처 표기가 필요하다.

배운 점: 클라우드를 감점으로 처리해 점수에 합쳤다면, 품질 점수 덕에 상위권에 남아 "쓸 수 없는 후보가 상위"가 됐을 것이다.

## 4. 기준을 넘지 못한 항목이 있다면, 다음에 무엇을 바꿔 다시 확인하겠습니까?

**넘지 못한 항목: 모음 시작 타이밍.** 평균 2.38프레임으로 기준(2프레임, 사람 수준 1.63)에 미달했다.
ko_01은 1.49로 통과했지만 ko_05가 3.26이었다. 나머지(시간 단축 98~99%, 재현율 1.0, 입 닫힘 7/8, 음량 기준선 대비 우위)는 통과했다.
→ 판정은 **조건부 구축** (`evaluation.md` 6장).

무엇을 바꿔 다시 확인할 것인가:
1. **정렬기를 MFA로 교체** (모델 선정 점수 1위). ko_05에서 오차가 큰 모음은 모두 Whisper가 단어 시작을 일찍 잡은 단어에 있었다.
   MFA는 대본 기반으로 음소 단위 시각을 주므로 원인을 직접 겨냥한다. **같은 라벨(ko_01, ko_05)로 다시 채점**해서 2.38이 얼마로 바뀌는지 본다.
2. **대본 힌트를 기본으로** 켠다. 이미 확인한 결과: 평균 2.38 → 1.86.
3. **라벨을 늘린다.** 지금은 2개 파일이라 결론이 흔들릴 수 있다. 영어(en_01)와 실패 사례도 라벨링한다.
4. **수정 시간을 잰다.** 자동 결과를 DCC 툴에서 고치는 시간까지 포함해야 실제 절감 폭이 나온다.

바꾸지 않을 것: 음소 → 입모양 → ARKit 커브 단계. 단어 시각이 맞은 ko_01에서 사람 수준이 나왔으므로 이 단계가 원인은 아니다.

입 닫힘 쪽 남은 문제 (기준은 통과했지만):
- 빠른 발화에서 닫힘이 1~2프레임뿐이라 덜 닫힘 (TTS fail_01) → MBP 최소 유지 프레임 보장
- 닫힘이 라벨에서 몇 프레임 벗어난 경우 1건, 잘못 닫힘 2건 → 정렬기 교체 후 다시 확인
